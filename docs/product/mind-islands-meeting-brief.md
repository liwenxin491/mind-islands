# Mind Islands Product Meeting Brief

## 1. Why we need this discussion
Right now, we have been improving features one by one. That has helped us make progress, but it can also create a pattern where we solve individual problems without always improving the whole product loop.

The key question for this meeting is:

**How should Mind Islands be designed so users keep giving us enough input, and feel enough value from the output to come back?**

## 2. Core product belief
Our product depends on user input.
If users do not input often enough, or deeply enough, the system cannot become meaningfully helpful.

So our main challenge is:
- reduce input friction
- increase useful input over time
- make output emotionally and practically valuable enough to reinforce return behavior

## 3. What we currently believe
### A. Input needs to be much easier
Users should not have to do too much work to start.

Implications:
- use fast check-ins
- use preset choices / taps where possible
- let users go deeper only if they want to

### B. Classification should not be a user burden
We probably should keep the island structure, but users should not need to classify things themselves before logging.

Implications:
- user inputs through AI log assistant / Quick Log
- system categorizes into Health / Work / Learning / Relationship in the background
- islands matter more for retrieval and review than for starting input

### C. Insights matter because they reward input
Users need to feel that input leads to something meaningful.

Implications:
- daily / weekly summaries are important
- insights should feel specific and encouraging
- avoid building a heavy dashboard too early

### D. DBT-inspired structures are promising, but should not dominate the default flow
We want to use things like ABC cards and emotional reflection cards.

Implications:
- good as optional deepening tools
- not ideal as the default first step
- better as generated or suggested after user input, not before it

### E. Quick Log and Self-Compassion should be related but distinct
We probably should not completely merge them into one indistinguishable chat.
But we also should not make them feel like unrelated systems.

Best current idea:
- one shared entry point
- two modes inside it:
  - Log with me
  - Sit with me

## 4. Proposed core user flow
### Primary daily loop
1. User opens app
2. User sees a very low-friction check-in
3. User taps quick responses or enters a short log
4. AI responds and organizes the input
5. Input becomes memory / task / reflection / support
6. User gets some useful return value
7. User is more likely to come back

## 5. Product priorities we should align on
### Priority 1
Make daily input easier.

### Priority 2
Make AI logging the main capture flow.

### Priority 3
Keep islands as the organizational system, but hide the complexity from the user during input.

### Priority 4
Use insights and summaries as positive reinforcement.

### Priority 5
Keep deeper self-compassion support available as a more intentional second layer.

## 6. Questions to decide together
1. How lightweight should the first check-in be?
2. Should the user ever manually choose a category during input?
3. How should Quick Log and Harbor relate in the UI?
4. What kind of daily / weekly summary would feel genuinely rewarding?
5. When should the system suggest a deeper structured card like ABC?

## 7. Suggested meeting outcome
By the end of the meeting, we should ideally leave with:
- one agreed core user loop
- one agreed entry strategy for input
- one agreed relationship between Quick Log and Harbor
- one agreed product priority order for the next development phase
